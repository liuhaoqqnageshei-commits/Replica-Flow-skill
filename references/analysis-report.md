# 深度分析报告模板

首次分析时读取。按实际网站填写，不用模板标题代替调查；完整报告在代码前展示。证据类型：源码/计算样式、画面观察、估计、未知。

## 任务、输入与基准

- 目标 URL / 路由、输出目录、保留或替换的内容。
- 真实材料路径与格式：工程/HTML/归档、PNG、录屏、notes；列出缺项。
- 已读取的需求澄清、设计拆解与质量评审模块路径。
- 源码优先核查结果：项目入口、路由、组件/动效对应路径，已确定参数与仍需画面核验的内容；源码不可用或不完整时记录限制。
- 验收设备；CSS 视口 W×H、DPR、缩放、截图内容区域。
- 原站采集日期、来源与已批准事项。

截图/录屏不全时附覆盖与补采集记录；先自行尝试补齐，再集中说明实际受阻项。能分析或在已有授权内实现的部分继续推进。

| 路由 / Section / 状态 | 已有证据 | 自行补采集结果与文件 | 来源：原站 / 本地参考 | 剩余缺项、原因与影响 | 可继续部分 / 待办 |
|---|---|---|---|---|---|

关键状态截图不能替代连续录屏的验证结论；无原站画面对照的部分标记为未完成视觉验证。

## 需求澄清 决策树与共同理解

记录相关决策分支、前置条件、事实来源、每轮问题与推荐答案、用户答复及未决事项，可引用 `state.md`。已确定偏好不重问，可自行核查的事实不问用户。存在未决分支时这是分析草案，继续不依赖它的取证并按协议提问。

| 决策分支 | 前置条件 / 证据 | 用户已确认选择或当前问题 | 受影响部分 / 可继续部分 | 状态 |
|---|---|---|---|---|

## 1. 整体结构与叙事

| 顺序 | Section / 时间轴阶段 | 目的与内容 | 流式 / sticky / fixed / pin | 显示区间与证据 |
|---|---|---|---|---|

解释滚动如何推进叙事、固定背景和 DOM 内容如何分层。Pinned 时附进度/相机/可见性阶段表，流式时附章节顺序与高度。

## 2. 设计系统

| Token / 角色 | 精确值 / alpha | 所属元素与状态 | 证据 / 可信度 |
|---|---|---|---|

分别记录：颜色；字体/字重/来源/回退；字号、行高、字距；网格与最大宽度；边距/间距/断点；圆角、阴影、描边。区分源码规则与当前视口计算尺寸，中文适配单列。

## 3. 逐节布局与组件

每节附对应画面与：外框/内部网格尺寸，标题/正文边界，组件与状态，媒体比例与裁切，留白，z-index/遮罩，内容映射，验收锚点。不要漏掉 Header、菜单/搜索、Footer 和详情交互。

## 4. 动画与交互

| 元素 / 选择器 | 触发及区间 | 属性起止值 | 时长 / ease / stagger | scrub / pin / loop | 反向 / 键盘 / 降级 | 证据 |
|---|---|---|---|---|---|---|

复杂动画另列：录屏文件、FPS/时间戳、关键帧截图、相机/主体/文字/裁切状态与实现分解。无录屏明确写未逐帧验证。

## 5. 技术栈

| 原站检测结果 | 证据与可信度 | 复刻方案 | 选择理由 / 兼容限制 |
|---|---|---|---|

先写检测，再写实现决定。版本不可确认时不填精确版本；用户锁定的栈明确标注。

涉及组件或动效选型时，按 [资源池](component-motion-libraries.md) 输出映射：原站元素和源码/画面依据 → 实际查到的具体候选及 URL/代码路径 → 采用方式、理由和需要修改的参数 → 依赖、许可及验证状态。可链接项目中的 `component-motion-map.md`。原站实现已适用时注明沿用思路；没有候选或检索受阻如实记录。不要只列库名，不额外新增逐库确认流程。

## 6. 难点与实施方案

- 复杂布局、中文密度、素材变化、滚动状态、shader 等难点及解决方法。
- 资产映射表：原位置 → 替换类型/文件、尺寸、构图、生成或授权来源、待确认项。
- 骨架/设计系统 → 逐 section → 动画专项 → 整页回归的顺序。
- 截图基准、布局容差、交互测试、降级测试与内部评分目标。
- 哪些部分能证实、哪些只能近似、还缺什么证据。

报告末尾汇总 需求澄清 已处理的决策、共同理解、方案和限制，以最终确认问题请求用户确认。该答复同时结束 需求澄清 并批准构建，不再追加同一方案的审批。只有同一任务中已存在明确确认的报告/方案及实施授权时，才记录依据并继续；泛泛的“继续分析”或局部答复不视为确认完整方案。
