# 组件与动效资源池

在分析阶段需要查找组件或动效实现时读取；构建和修正时沿用已选映射。用途是为原站效果寻找可调整的实现，保持原站的布局与交互目标。以下是可选的优先资源池，不是必须安装的依赖清单，也不限制使用更适合的工具。

## 从原站需求到可用候选

1. **先查原站实现。** 对照页面入口、组件、样式及动画调用，记录目标元素、CSS 动画/时间线/物理/Canvas/WebGL 等实现方式。读实际调用和参数，不只看依赖列表。原站规则已明确且现有工程能实现时，可直接沿用思路，无需为使用资源池而另找替代。
2. **描述效果后检索。** 用结构和行为查相关目录，例如“可展开 Agent 过程”“滚动联动遮罩”“重力文字”“液态融合”。先查已连接且具备相应能力的工具；再查官方文档索引、registry、仓库或网页。工具不存在不等于库不可用，也不自动安装 MCP 或技能。
3. **读具体实现。** 找到候选后查看真实预览（工具允许时）、源码、配套文件、依赖、可调参数及许可证。只读到文档时写“文档已核对、预览未验证”；未获得源码时不能写“源码已确认”。候选页面打不开时尝试其官方目录或仓库，仍受阻就记录结果。
4. **比较采用成本。** 判断它能否表达原站的触发、轨迹、状态及反向行为；检查框架、样式版本、客户端边界、包体和与已有动画控制的冲突。选用、改造、只参考算法或不采用均需给出与目标相关的理由。无需为简单原生效果引入大依赖；长滚动时间线和定制 3D 也不必强套现成 UI 组件。
5. **纳入报告。** 保存选择和真实来源到项目的 `replica/component-motion-map.md`，或并入现有 brief。分析阶段可创建分析工具、报告和取证文件，仅核查组件文档/源码，不先安装复刻组件或创建网站试作页；涉及关键取舍纳入 需求澄清，相同方案在最终报告中一并确认。

| 页面 / 元素 | 原站代码、参数及画面证据 | 检索资源与具体候选 URL / 源码路径 | 采用方式及理由 | 需调整的结构 / 参数 | 依赖 / 许可证 | 验证状态 |
|---|---|---|---|---|---|---|

原站可直接实现、未找到候选、付费内容不可用、访问受阻，均在实际涉及的行中记录；不要虚填候选或把“不采用”写成“已集成”。无需为原站没有的功能建立无关映射。

## 确认后的接入与动效复验

- 根据项目现状选择复制必要源码、按官方 registry 安装单个组件，或参考算法重写。安装前检查命令会修改的文件，保留现有组件和配置；不要一次安装整个资源池。记录实际采用的版本或源码来源、必要依赖和修改点，保留适用版权及许可声明。
- 先统一到复刻版的字体、颜色、间距和组件结构，再对齐触发点、位移/缩放/旋转/透明度、时长/缓动/弹簧、错开顺序、遮罩/图层及退出行为。原站没有的默认入场、循环或悬停效果应关闭。资料无法证实的参数保留估计标记。
- 同一个元素的同一个运动属性应有清楚的控制来源，避免库默认动画与自定义滚动时间线同时争用。区分“滚动触发后按时间播放”和“滚动进度控制播放”，按原站行为接入。
- 在相同视口与时间点/滚动进度核对开始、中间、结束和停留阶段，并实际检查反向操作、快速输入/滚动、停止后收敛及离开重入。物理或随机效果比较规则、范围和交互响应；只有可控时才固定随机种子，不用单帧像素一致作为唯一标准。
- 保留原站参考与本地复刻的独立证据，按主流程记录差异并迭代。复杂液态、物理或 3D 组件额外检查适用的裁切、清晰度、性能和减少动态表现；未执行的场景写未验证。组件库演示正常不代表接入本项目后已通过。
