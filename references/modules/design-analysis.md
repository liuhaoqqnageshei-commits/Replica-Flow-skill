# 设计拆解模块

## 证据路径

从源码入口追踪实际组件、选择器、资源和动画调用，随后用运行画面核验。区分声明依赖、包中存在代码、当前路由实际执行三种事实。没有完整工程时用可读的HTML、bundle与归档取证，无法查明的部分才观察推导。

每个重要结论附来源：文件/选择器、截图及视口状态，或录屏时间戳；标注已证实、观察、估计、未知。保留原始资料，不直接运行第三方生产包作为复刻成品。

## 逐节规格

- 叙事与文档流：section边界、布局、普通滚动、sticky/fixed层及持续区间。
- 设计规则：颜色含透明度、字体与字重、字号/行高/字距、网格、间距、断点、圆角和阴影。
- 素材框：原位置、宽高比、裁切、主体方向、留白、明暗、层叠及替换映射。
- 交互：菜单、hover、搜索、弹层、焦点、键盘和反向关闭状态。
- 动画：触发条件、属性起止值、持续时间、缓动、错开、循环、离开重入、正反向和减少动态状态。

长截图中的固定背景重复或空白只算线索，不能据此认定 pinned timeline。复杂滚动/3D动画应结合真实录屏与源码；没有连续证据时明确验证限制。

## 从证据到构建

把原站元素映射到可实现组件与参数。清楚的原生实现优先；需要库时核查具体源码、预览、依赖与许可证。报告确认后再安装和实施。逐节完成同条件截图、并排及原尺寸观察；差异区分实现错误、有意替换、批准适配和证据不足。
