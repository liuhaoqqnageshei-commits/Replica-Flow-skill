# 需求澄清模块

先读当前会话与任务状态。把事项分为可自行核查的事实，以及必须由用户选择的范围、内容、设备、素材策略与关键取舍。

对未决选择建立依赖：本轮只询问所有前提已知的事项；依赖未回答选择的问题留到下一轮。每题编号、简述影响并给推荐答案，推荐不等于批准。等待答复时继续不依赖它的取证。

用户答复后更新状态，仅追问仍未解决或新解锁的选择。工具可查到的组件、动画参数、文件路径与真实网页状态由 Agent 自行核查，不让用户代查。若宿主支持并允许委派，可把独立事实核查交给子代理；否则主代理完成。

相关选择都处理后，在完整分析报告中汇总共同理解，取得一次明确确认后进入构建。已有批准的方案不重复访谈；后续局部反馈直接修复。只有关键范围发生变化时才重开受影响分支。

建议提问格式：

❓ Q1 — 页面范围：完整首页，还是包含哪些独立详情页？

➡️ 推荐：依据用户原始要求给出具体建议及影响。

不要把示例变成固定问卷。用户已给出的范围和偏好直接作为已解决节点。
